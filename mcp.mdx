The Wirebox MCP server gives any [Model Context Protocol](https://modelcontextprotocol.io) client access to an agent identity: its mailbox, its iMessage conversations, and the texts received on its phone number. Clients can read incoming messages, send and reply to email and iMessage, search a mailbox, and check which identity the connection is acting as.

---

## Connect

Wirebox runs a hosted MCP server over Streamable HTTP. There is nothing to install: add the URL to your client.

```text
https://api.wirebox.sh/api/v1/mcp
```

You can authenticate in two ways:

- **OAuth sign-in** — Clients that support OAuth for remote MCP servers, such as Claude Code. The client opens a browser, you sign in to Wirebox and approve. No API key to copy.
- **API key** — Headless setups and clients without OAuth support.

### Sign in with OAuth

In Claude Code:

```bash
claude mcp add --scope user --transport http wirebox https://api.wirebox.sh/api/v1/mcp
```

Then start a session, run `/mcp`, choose `wirebox`, and select **Authenticate**. A browser window opens on `wirebox.sh` showing the application that is asking for access. Check the name and the address it will return to, then approve.

An OAuth connection can call the MCP tools below and nothing else: the API key, billing, phone number, and domain endpoints reject it. It acts for your whole organization rather than one agent identity; see [Choosing an identity](#choosing-an-identity).

### Authenticate with an API key

Send your API key in one of three ways, depending on what the client supports:

- **`Authorization` header** — `Authorization: Bearer wb_live_...`
- **`X-API-Key` header** — `X-API-Key: wb_live_...`
- **Query parameter** — `https://api.wirebox.sh/api/v1/mcp?apiKey=wb_live_...`

Use the query parameter only for clients that cannot set custom request headers.

A typical remote server entry looks like this:

```json
{
  "mcpServers": {
    "wirebox": {
      "url": "https://api.wirebox.sh/api/v1/mcp",
      "headers": {
        "Authorization": "Bearer wb_live_your_api_key_here"
      }
    }
  }
}
```

Client-specific walkthroughs:

- [**Cursor**](/integrations/cursor) — Add Wirebox as a remote MCP server in Cursor.
- [**Claude Code**](/integrations/claude-code) — One CLI command, or a project-level `.mcp.json`.

## Tools

The hosted endpoint exposes twelve tools:

| Tool | What it does |
| :--- | :--- |
| `wirebox_whoami` | Show the identity the connection acts as, including its phone number, plus iMessage router status. |
| `wirebox_mail_list` | List mailbox messages (`limit`, `offset`, `status`). |
| `wirebox_mail_search` | Full-text search across the mailbox, ranked by relevance (`query`, `limit`). |
| `wirebox_mail_get` | Read one message in full (`messageId`), including attachments. |
| `wirebox_mail_send` | Send an email (`to`, `subject`, `body`). |
| `wirebox_mail_reply` | Reply on an existing thread (`messageId`, `body`, optional `html`, `replyAll`, `to`, `cc`, `bcc`). |
| `wirebox_mail_delete` | Permanently delete a message (`messageId`). |
| `wirebox_imessage_list_conversations` | List iMessage conversations with unread counts. |
| `wirebox_imessage_get_messages` | Read a conversation's message history (`conversationId`). |
| `wirebox_imessage_send` | Send an iMessage (`text`, plus `to` or `conversationId`). |
| `wirebox_sms_list` | List texts received on the agent's phone number, newest first (`unreadOnly`, `from`, `limit`, `offset`). |
| `wirebox_sms_get` | Read one text in full (`messageId`), including MMS media links. Marks it read. |

Most tools accept an optional `identity` argument for choosing among multiple identities when the credential allows it.

Text messages come from outside senders. The SMS tools tell the model to treat their content as data, not instructions, but a connected client should still be given only the access it needs.

## Choosing an identity

What a connection can do depends on how it authenticates:

* **Identity-scoped API key** — the key is bound to one agent; every tool call acts as that identity.
* **Organization API key or OAuth sign-in** — tools accept an `identity` argument. Without one, the connection acts as the organization's first agent identity, and `wirebox_whoami` reports which.

Use an identity-scoped key wherever the agent answers people you do not control, such as a messaging bridge. With an organization-wide credential, content in an incoming message could try to steer the `identity` argument; a scoped key enforces the identity on the server.

---

## Verify the connection

Ask the client to call `wirebox_whoami`. It returns the handle, mailbox address, and iMessage status of the identity the connection acts as. If the handle is not the one you expected, pass `identity` or reconnect with an identity-scoped key.

---

## What is not included

MCP exposes the day-to-day communication surface — mailbox reads, search, sends, replies, deletes, and iMessage. Everything else stays in the REST API and SDKs:

* Email drafts, mail rules, and security policies
* Phone number provisioning, sending texts, and calls
* Tunnel management and webhook configuration

The MCP server also does not watch channels in the background. It acts only when the client invokes a tool. To wake an agent when a message arrives, subscribe a webhook and run a process that feeds the event to your model — see [Webhooks](/capabilities/webhooks).

## Data access and actions

A connected client can read the communication content and account data returned by the tools it is allowed to call, and can request actions such as sending emails or iMessages and deleting messages. Review confirmation prompts before approving sends or deletions, and only connect clients you trust — delivered data is handled under that client's own terms and privacy policy.

To cut access, revoke the API key in the [Console](https://wirebox.sh/console/keys) or disable the connection in the client. An OAuth connection is removed by deleting the server in the client; Wirebox has no screen for revoking OAuth grants. Inbound and outbound mail rules remain in force regardless of which client is connected; see [Mail Rules & Policy](/api-reference/mail/rules).

## Troubleshooting

<AccordionGroup>
  <Accordion title="No Wirebox tools appear">
    **Likely cause**: Server not connected.  
    **Fix**: Check the server entry in the client configuration and restart the client.
  </Accordion>

  <Accordion title="Tools return an authorization error">
    **Likely cause**: API key is invalid or revoked.  
    **Fix**: Create a new key in the [Console](https://wirebox.sh/console/keys) and update the configuration.
  </Accordion>

  <Accordion title="Tools act as the wrong identity">
    **Likely cause**: Organization key or OAuth sign-in with a different default.  
    **Fix**: Pass `identity`, or use an identity-scoped key.
  </Accordion>

  <Accordion title="Email sends are refused">
    **Likely cause**: Outbound guardrails or rule restrictions.  
    **Fix**: Check [Mail Rules & Policy](/api-reference/mail/rules).
  </Accordion>
</AccordionGroup>
