---
title: "Claude Code"
description: "Connect Claude Code to a Wirebox agent identity over the remote HTTP endpoint."
---

Claude Code reaches Wirebox as a remote HTTP MCP server. Sign in with your Wirebox account, or use an API key for headless setups. You can also commit a project-level `.mcp.json` so every session in the repository has it.

## Sign in with OAuth

```bash
claude mcp add --scope user --transport http wirebox https://api.wirebox.sh/api/v1/mcp
```

Start a session, run `/mcp`, choose `wirebox`, and select **Authenticate**. A browser window opens on `wirebox.sh`; check the application name and the address it returns to, then approve. The connection can use the Wirebox MCP tools and nothing else, and it acts for your whole organization, so tools accept an `identity` argument.

## Connect with an API key

For headless setups, or to pin the connection to one agent with an identity-scoped key:

```bash
claude mcp add --transport http wirebox https://api.wirebox.sh/api/v1/mcp \
  --header "Authorization: Bearer $WIREBOX_API_KEY"
```

By default the server is added to the current project's local scope. Add `--scope user` to make it available in every project, or `--scope project` to write it into the shared `.mcp.json`.

## Connect with a project config

Commit a `.mcp.json` in the repository root so the whole team gets the same server:

```json
{
  "mcpServers": {
    "wirebox": {
      "type": "http",
      "url": "https://api.wirebox.sh/api/v1/mcp",
      "headers": {
        "Authorization": "Bearer wb_live_your_api_key_here"
      }
    }
  }
}
```

Anyone using this file should use their own key — or an identity-scoped key if the project should act as a single agent.

## Verify

List the configured servers, then ask Claude to call `wirebox_whoami`:

```bash
claude mcp list
```

Inside a session, `/mcp` shows connection status and the tools each server exposes. `wirebox_whoami` returns the identity the connection acts as — if it is not the agent you expected, pass `identity` or switch to an identity-scoped key.

## What Claude Code can do

* List, search, read, send, reply to, and delete email in the agent's mailbox
* List and read iMessage conversations, and send iMessages
* List and read the texts received on the agent's phone number
* Check which identity the connection acts as

Sends follow the identity's [mail rules and policy](/api-reference/mail/rules), and nothing happens until Claude calls a tool.

## Troubleshooting

| Symptom | Fix |
| :--- | :--- |
| `Failed to connect` | Check the URL and that the key is valid. |
| Tools return an authorization error | The key is invalid or revoked — create a new one and re-add the server. |
| Server missing in a new session | Re-add it with `--scope user`, or commit `.mcp.json` at the project root. |
| Tools act as an unexpected identity | Pass `identity`, or use an identity-scoped key. |

See [MCP](/mcp) for the full tool catalog and how identities are chosen.
